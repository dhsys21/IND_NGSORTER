1. 단축된 에러코드 규칙
======================================================================
현재 FMS 보고값 = 분류번호 2자리 + 원인번호를 최소 3자리로 표현한 10진수.
보통 5자리이며, 숫자로 전송합니다. 문자열에 임의로 0을 붙이는 방식은 아닙니다.

분류 10 : 서보 보드 시스템 알람 (sscGetAlarm / SSC_ALARM_SYSTEM)
분류 20 : 축별 서보 알람       (sscGetAlarm / SSC_ALARM_SERVO)
분류 30 : 축별 운전 알람       (sscGetAlarm / SSC_ALARM_OPERATION)
분류 40 : 보드 시스템 상태 오류 (sscGetSystemStatusCode의 E***)
분류 50 : NGSORTER 로컬 설비/시퀀스/FMS 오류

예)
  도어 #1       : 내부번호 121       -> 50 + 121 = 50121
  취출 오류     : 내부번호 201       -> 50 + 201 = 50201
  FMS 수신 알람 : 내부번호 307       -> 50 + 307 = 50307
  서보 1Ah      : 16진수 1A = 10진수 26          -> 20026
  시스템 E40Bh  : E를 제외한 40B = 10진수 1035   -> 401035

내부 변수명 FmsCellTrackOut 등은 프로그램 식별자이고 실제 보고값은 숫자입니다.
서보 원래 코드와 FMS 보고코드는 진법이 다릅니다. 1Ah를 10진수 1로 읽으면 안 됩니다.
원인번호가 3자리를 넘으면 Encode()는 자릿수를 늘려 모든 숫자를 보존합니다.
예: 서보 26 -> 20 + 026 = 20026, 시스템 1035 -> 40 + 1035 = 401035.
0은 해당 원인의 정상/해제를 뜻하며 활성 ErrorNo 배열에 넣지 않습니다.

이번 변경 및 적용 주의
  기존 50000307 -> 50307, 50000308 -> 50308, 50000121 -> 50121.
  기존 20000026 -> 20026, 40001035 -> 401035.
  분류번호는 유지하고 원인번호의 최소 자릿수를 6자리에서 3자리로 줄였습니다.
  ErrorNo 배열과 ErrorLevel 모두 같은 단축 코드로 보고합니다.
  FMS가 보내는 수신 ErrorNo(예: 9001)는 변환하지 않습니다.
  FMS 측에서도 새 코드표를 사용해야 합니다. 기존 로그 파일은 변경하지 않습니다.
  수정된 EXE를 빌드/적용한 이후의 보고부터 변경됩니다.

2. FMS로 보내는 태그와 FMS에서 받는 태그
======================================================================
[설비 -> FMS]
  NGS.F1NGS01.EquipmentStatus.Trouble.ErrorNo
    UInt32 배열. 현재 활성화된 중복 없는 에러코드를 발생 순서로 보고.
  NGS.F1NGS01.EquipmentStatus.Trouble.ErrorLevel
    현재 구현은 첫 번째 활성 에러의 전체 코드. 없으면 0.
    이름과 달리 '심각도 1/2/3' 또는 코드 앞자리만 보고하는 값이 아닙니다.
  NGS.F1NGS01.EquipmentStatus.Status
    등록 에러가 있으면 4. 에러가 없을 때 Pause=8, 작업=2, Idle=1.
    따라서 Pause 중에도 미해제 에러가 있으면 Status는 8이 아니라 4입니다.

예)
  ErrorNo    = [50121, 50304]
  ErrorLevel = 50121
  Status     = 4
  모든 에러 해제 후: ErrorNo=[], ErrorLevel=0.
  에러 해제만으로 축 이동/시퀀스가 자동 재개되지는 않습니다.

같은 서보 주 알람이 여러 축에서 발생하면 배열에는 한 번만 나옵니다.
관련 축/읽기 원인이 전부 해제되어야 해당 코드를 제거합니다.
읽기 실패/통신 단절을 정상으로 판단해 기존 에러를 지우지 않습니다.
축 번호와 세부 서브코드는 서보 진단 화면/로그에서 확인해야 합니다.

[FMS -> 설비]
  NGS.F1NGS01.FmsStatus.Trouble.Status
  NGS.F1NGS01.FmsStatus.Trouble.ErrorNo

예: FMS 수신 ErrorNo=9001인 경우
  9001은 FMS가 정한 원래 번호입니다. 이 소스에는 그 번호의 의미표가 없습니다.
  설비에서 FMS로 보고하는 'FMS Trouble 발생' 코드는 별도 50307입니다.
  즉 수신 번호 9001과 설비 보고 번호 50307을 혼동하면 안 됩니다.
  새 수신 알람은 Pause 및 알람창 표시.
  현재 소스는 작업자가 START/Retry/Restart로 인정한 같은 알람에 한해
  계속 ON이어도 재진행을 허용하며, 실제 안전 인터락은 계속 확인합니다.
  인정했다고 50307을 지우거나 FMS 수신 태그를 강제로 OFF하지 않습니다.

4. 화면 메시지와 FMS 코드의 관계 / 확인 시 주의
======================================================================
- 모든 에러 문구에 1:1의 별도 번호가 있는 구조는 아닙니다.
  공통 FormError 경로의 AUTO blocked, Init Work blocked, Restart interlock,
  Sorting initialization failed 등은 공통 코드 50204를 사용할 수 있습니다.
  취출/삽입 복구 창은 각각 50201/50202입니다.
  정확한 원인 문장, 채널, 그리퍼 번호, 축, 기대값/현재값은 화면과 로그를 확인합니다.

- FMS 오류는 거래별로 묶여 있습니다.
  같은 50302라도 Response ON 대기, 데이터 검증, Response RESET=0 대기
  중 어느 곳에서 실패했는지는 별도 상세 로그로 구분해야 합니다.
  ErrorNo만으로 실패한 태그/셀 필드까지 특정할 수 없습니다.
  Close/Retry 버튼을 눌렀다고 응답 실패 코드가 바로 해제되지는 않습니다.

- 셀 감지, 센터링 상실, 서보 Open/ON/Home 미완료 등의 인터락은
  호출되는 공통/로봇/이동/취출/삽입 오류 경로에 따라 보고 코드가 달라질 수 있습니다.
  모든 인터락에 독립된 로컬 번호가 정의되어 있는 것은 아닙니다.
  단순 ShowMessage, 로그만 남기는 경로는 그 호출만으로 ErrorNo가 추가되지 않습니다.

- 50125는 내부 이름이 ServoNotRunning이지만 실제 등록 위치는
  보드 상태/알람 읽기 실패입니다. 'Servo OFF'와 동일한 뜻이 아닙니다.
  보드가 보고한 운전 알람 B2h(Servo is off)는 30178로 구분됩니다.

- CC-Link/PLC 통신 오류는 이전 정상 연결 이력이 있어야 등록됩니다.
  프로그램 시작부터 미연결이면 해당 통신코드가 반드시 올라간다고 볼 수 없습니다.

- 서보 API 함수 자체의 반환 오류는 기존 로그에도 남습니다.
  API 반환값을 E*** 보드 시스템 상태 오류로 임의 변환하지 않습니다.
  IDE의 Access violation, EReadError, EIdNotConnected 같은 실행 예외 또한
  이 문서의 로컬 오류 열거값에 독립 코드로 정의되어 있지 않습니다.

- Door #3, 극성이 확인되지 않은 CP/MS 접점은 이 로컬 코드표에 없습니다.
  온도/연기 등은 별도 EnvStatus 태그 경로이며 임의의 신규 코드로 넣지 않았습니다.

6. 과거 MES 번호와 현재 FMS 코드 구분
======================================================================
FormMain::GetAlarmMsg(1~27)에 과거 메시지 번호가 남아 있습니다.
이 값은 현재 NGSorterErrors::Local/FMS ErrorNo와 다른 번호체계입니다.
예를 들어 과거 25는 Door #1이지만 현재 내부번호는 121, 보고값은 50121.
과거 번호에 무조건 50000을 더해 현재 코드로 변환하면 안 됩니다.
과거 메시지 목록은 아래와 같습니다. 현재 활성 FMS 보고 매핑으로 사용하지 마십시오.

1~2   : MES Source tray information error / reply timeout
3~4   : MES Target tray information error / reply timeout
5~6   : MES Target ID matching error / timeout
7~8   : MES Source tray transfer-out error / timeout
9~10  : MES Target tray transfer-out error / timeout
11~12 : MES send-event error / timeout
13~14 : MES Source ID matching error / timeout
15    : Source tray gripper-down timeout
16    : Source tray gripper-up timeout
17    : Source tray gripper-down collision
18    : Target tray gripper-unchuck timeout
19    : Target tray gripper-up timeout
20    : Source tray Cell No / Gripper No mismatch
21    : Target tray gripper-down collision
22    : Target tray gripper-down timeout
23    : Target tray Cell No / Gripper No mismatch
24    : NG count exceeded the configured limit
25    : DOOR #1 Open
26    : DOOR #2 Open
27    : Emergency stop
